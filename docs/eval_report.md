# 检索效果评估报告（阶段 2 · M1）

> 评估时间：2026-09-17 ｜ 执行：`python -m scripts.evaluate_retrieval`（backend 目录）

## 环境

| 项 | 值 |
|----|----|
| 知识库 | 3 份示例文档，共 7 块（评估时含 1 块已清理的验证用测试文档） |
| 向量模型 | `BAAI/bge-small-zh-v1.5` |
| 重排模型 | `BAAI/bge-reranker-base`（本地 CrossEncoder） |
| 测试集 | `datasets/test_qa/qa_samples.json`，24 条 |
| 评估指标 | Hit@K（文档级命中：检索 Top-K 中出现测试样本标注的来源文档） |
| 重排策略 | 向量召回 Top-20 → 精排 → 取 Top-K |

## 结果

| 方案 | Hit@1 | Hit@3 | Hit@5 | 未命中数 |
|------|-------|-------|-------|---------|
| 纯向量（baseline） | **66.7%**（16/24） | 91.7%（22/24） | 91.7%（22/24） | 2 |
| 向量 + bge-reranker 精排 | **79.2%**（19/24） | **95.8%**（23/24） | **95.8%**（23/24） | 1 |

## 结论

1. **精排显著提升首条命中**：Hit@1 由 66.7% → 79.2%（+12.5pp），说明交叉编码器对"问题与块的相关性"判别明显优于向量距离。
2. **Top-3 内基本覆盖**：精排后 Hit@3 达 95.8%，适合作为 Agent 的最终上下文输入窗口。
3. **残余未命中**（精排仍失败的 1 条）：
   - 「病死鹅应该如何处理？」→ 命中文档未出现"鹅养殖生物安全与疫苗免疫程序"（知识库规模小、措辞差异导致语义偏移）。
4. **噪声数据提示**：向量库中存在 M3 验证时上传的「测试文档」，对部分问题造成干扰（纯向量基线中「雏鹅出壳 24 小时内预防小鹅瘟」即被其抢占首位，重排已纠正）。

## 下一步（M2 规划）

- 多 Query 改写召回（DeepSeek 生成 2-3 个改写 query 合并去重），提升跨文档检索覆盖面；
- 扩大知识库规模（真实 PDF）后复测，Hit@3 目标 ≥ 97%。
